The November 15 UTC qualification combines 377 opening GETs with 377 separately dated closing GETs. All 338 logical controls close, including every make, model and arrivals page. That historical closing re-read every control; current runs close as described below. The complete union has 2,382 observations: 2,297 accepted donors, 83 rejects or quarantines and two duplicates. Small badge discrepancies remained diagnostics. Published membership, donor fields and supplier ownership must reconcile.

The preserved AD80068 destination failure remains quarantined and was never retried. Its valid VIN and both conflicting VIN groups remain presence evidence, protecting prior records during reconciliation. Missing optional metadata remains null. The source retains the 10% rejection, 25% duplicate, 50% previous-count and 765-donor minimum guards. They run over read and carried pages, so carried pages can keep them satisfied while live model pages break. The read plus carried model cards, each model counted only up to its own badge, must therefore cover at least 95% of the opening model badge sum, or the run stages nothing and keeps the last accepted census. The qualification graph covered 99.5% (no page exceeded its badge), and emptying any one of its six sweep slices drops coverage to between 77% and 87%, so one broken day fails. While the last accepted run is under 6 days old, the read plus carried cards must also cover 97% of the cards the last accepted census held for every model, each reference lowered by any drop in that model's badge (the shared replay floor). Cutting any one sweep slice of the qualification graph to a single card per model leaves between 79.3% and 89.4% of those cards (and between 78.9% and 88.9% of the badges), so that breakage fails on its first day too.

Each run reads the about, contact and make directory pages, every make menu at its slash URL (one GET instead of the native 301 plus 200), and the arrivals page. When the last accepted census is from the same day or the day before, it then reads a model page only when the model is new, its menu badge changed, an arrival under it is missing from its carried page, its page is short and unconfirmed, its evidence is six run days old, or it falls in that day's one-sixth sweep slice. Every other model carries its last accepted page. A model is expected to list its badge plus any surplus its last accepted page listed above that page's own badge; the surplus carries across badge changes. After a missed, failed or rejected run, every model page is read. Closing re-reads about, contact, the make directory and every model read this run whose card count differs from its badge or falls below its expected cards, and stops the run if any of them changed, so a short page that does not repeat is never carried forward. A page below its badge that closing confirmed is carried, unless the run followed an outage of 6 or more days; any other page below its expected cards is read again on the next run. Carried models are not re-read; other per-model changes during a run surface as badge changes in the next run's opening. A missing, unreadable or incompatible previous census reads every model page.

The shared rules (gap full reads, short-page confirmation, closing reads, both coverage floors and the outage path) are in [Incremental model census](model-census.md). Denton specifics: the badge floor is 95% (`DENTON_MINIMUM_BADGE_COVERAGE`), because the qualification graph covered 99.5% and losing one sweep slice drops it below 89%. Closing confirms short pages. Estimated from the qualification graph, a normal day is about 110 GETs plus a closing re-read of each short page read that day. A cold census, and the full read the day after a missed, failed or rejected run, is about 345 GETs: 338 opening controls, three closing ownership and directory pages and the four short pages (TOWN & COUNTRY and three pages one card short). The earlier figure of about 341 is historical and predates closing re-reads of short pages.
