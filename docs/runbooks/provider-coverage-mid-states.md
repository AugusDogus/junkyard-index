### Enumeration and request budget

The native `POST /VehicleDealerSearch` form with `hdnChangeDisplay=card` returns each entire roster in one response. The existing parser reconciles its advertised total and every tenant-bound vehicle destination. No per-vehicle detail crawl is needed. A separately fetched closing card roster verifies the whole opening census.

The two additions require **four Hollander requests per daily run**, two per yard. Existing native makes and permanent successful VIN-to-make seeds avoid repeated decodes. Only newly encountered valid VINs without a native make need vPIC, in batches of at most 50. The qualification added 990 successful VIN-to-make results through 21 vPIC requests: 772 Rowland VINs in 16 requests, 218 Midvale VINs in five requests. Native makes always take precedence.

Initial qualification made 30 logical requests: four roster POSTs, two About Us GETs, 21 vPIC POSTs, two Census GETs and one business-site GET. The initial acquisition overlapped some requests to different services; it did not meet the requested fully serial acquisition policy. Original receipts preserve that history. Total admitted-yard acquisition is **34 requests**, including the four replacement roster reads. A replacement four-request opening/closing acquisition uses one serial process and at least 3.5 seconds between completed responses and subsequent request starts. The production connector already has a shared Hollander/vPIC semaphore and a three-second completion gap.

The combined budget is 106 Hollander HTML requests and 329 logical decode operations, 435 logical operations total. With the shipped seed, one historical unresolved VIN still needs a live vPIC retry, so the unchanged seeded census uses 107 provider requests. Its complete serialized checkpoint is 11,671,187 bytes, below the existing 32 MiB bound; workflow steps continue to carry private snapshot references. `mid-states/daily-budget.json` records these offline measurements. These are request and size counts, not a live runtime guarantee.

Original HTTP bodies, byte counts, SHA-256 receipts, addresses, geocodes and vPIC responses are under `hollanderstores-test-fixtures/mid-states`. Tests replay them offline through the production parser and snapshot validator. No provider, production DB, deployment or merge is needed for tests.
